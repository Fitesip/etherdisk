# Etherdisk для ПК

Приложение для Windows, macOS и Linux на [Tauri 2](https://v2.tauri.app): страницы сайта (`web/`) собираются статически и встраиваются в приложение, окно — системный WebView (на Windows — WebView2). Шифрование то же, что на сайте: файлы шифруются и расшифровываются внутри приложения, сервер видит только шифротекст.

Чем отличается от сайта:

- **Код страниц лежит в самом приложении.** Взломанный или подменённый веб-сервер не может отдать приложению другой JavaScript: обновляется оно только новой версией.
- **Ссылки на другие сайты** (Etherscan, кошельки, документация) открываются в браузере; приложение показывает только свои страницы. WebView2 не сообщает приложению о ссылках в новое окно (`target="_blank"`, `window.open`), поэтому `src-tauri/src/links.js` превращает их в обычный переход, который уже уходит в браузер.
- **Файлы можно перетащить в окно** для загрузки, как на сайте.
- **Второй запуск** открывает уже запущенное окно; размер и положение окна запоминаются.
- **Вход — только через WalletConnect** (QR-код, подпись в кошельке на телефоне): расширения браузера вроде MetaMask во встроенный WebView не попадают.

## Как это устроено

- Страницы отдаёт обработчик схемы `app://` (`src-tauri/src/main.rs`): `app://localhost` на macOS и Linux, `http://app.localhost` на Windows. Страницы с номером диска и ссылки общего доступа собраны один раз, для `_` (`/drive/_`, `/s/_`), и отдаются для любого номера; номер страница берёт из адреса (`web/src/lib/route-param.ts`).
- CSP — та же, что у сайта (`web/next.config.ts`): в статической сборке она лежит в `<meta>` каждой страницы, а приложение повторяет её заголовком ответа.
- Запросы к API идут на `NEXT_PUBLIC_API_URL` с адреса приложения, поэтому сервер должен разрешать его в `CORS_ORIGINS`. Вход подписывается для сайта (`NEXT_PUBLIC_SITE_URL` → домен в сообщении SIWE совпадает с `SIWE_DOMAIN` сервера), ссылки общего доступа тоже ведут на сайт.

## Сервер и WalletConnect

- В `deploy/server.env`: `CORS_ORIGINS=https://etherdisk.app,http://app.localhost,app://localhost`, затем `docker compose up -d server`.
- В [Reown Dashboard](https://dashboard.reown.com) у проекта WalletConnect в списке разрешённых доменов (если он задан) должны быть `app.localhost` и `localhost`, иначе окно подключения не откроется.

## Сборка

Нужны Rust, Node.js 24, `wasm-pack` (как для `web/`) и [системные зависимости Tauri](https://v2.tauri.app/start/prerequisites/) (на Windows — WebView2, он уже есть в Windows 10 и 11).

```bash
cd desktop
cp .env.example .env     # адрес API и сайта, сеть, контракт, RPC, WalletConnect
npm ci
npm run build            # статическая сборка web/ → web/out, затем установщик
```

Установщик для Windows — `src-tauri/target/release/bundle/nsis/Etherdisk_<версия>_x64-setup.exe` (ставится для текущего пользователя, без прав администратора). На macOS и Linux та же команда собирает `.dmg`, `.AppImage` и `.deb`.

В сборку попадают только настройки из `desktop/.env` (или переменных окружения): `web/.env.local` не используется, так что локальные настройки разработки в релиз не уйдут.

CI собирает установщик для Windows на каждый PR (задача «Desktop app», артефакт `etherdisk-windows`). WalletConnect в нём работает, если в репозитории задана переменная `WC_PROJECT_ID` (Settings → Secrets and variables → Actions → Variables).

## Разработка

Интерфейс удобнее править на сайте (`cd web && npm run dev`). Приложение берёт страницы из `web/out`, поэтому после правок в `web/`:

```bash
npm run web              # пересобрать страницы
npm run dev              # запустить приложение (tauri dev)
```

Проверки: `cd src-tauri && cargo test && cargo clippy --all-targets -- -D warnings`.

## Ограничения

- Установщик не подписан сертификатом: Windows SmartScreen предупредит при первом запуске («Подробнее» → «Выполнить в любом случае»). Для macOS нужна подпись и нотаризация Apple, иначе Gatekeeper не даст открыть приложение.
- Автообновления пока нет: новая версия ставится поверх старой.
